# 長い会話と資料をAFM 3 Core Advancedで読む

定型通知を含む合成履歴7問では、同一の文を辞書にまとめると、旧版の4問正解から7問正解になった。回答と検証のために送った入力は合計31,088から5,908トークンに減った。異なる発言が続く資料では、各区間から根拠を選んでから回答する方式を試した。新しく取り分けた6問で3問正解から5問正解になり、合計入力は10,856から14,103トークンに増えた。[最終版のケース別記録](results.jsonl)

## 用途と設定

| 資料と方式 | 正解数（旧版 → 新版） | 全生成に送った入力の合計 | CLI完了時間の中央値 |
|---|---:|---:|---:|
| 同文が繰り返される履歴7問、`--compact` | 4/7 → 7/7 | 31,088 → 5,908 | 2.50秒 → 0.98秒 |
| 内容が変わる追加資料6問、`--compact` | 3/6 → 3/6 | 10,856 → 10,856 | 1.46秒 → 1.66秒 |
| 同じ追加資料6問、`--compact=evidence` | 3/6 → 5/6 | 10,856 → 14,103 | 1.46秒 → 2.07秒 |
| 日本語・英語の既存資料QA40問、`--compact` | 26/40 → 26/40 | 両方式で元の読解処理を使用 | — |

反復7問の内訳は開発用5問で3/5→5/5、追加2問で1/2→2/2。異なる記録の開発用5問は、旧版2/5、辞書方式2/5、根拠選択4/5だった。表は各条件1回の値で、繰り返し試行による分散は測っていない。合成20問と既存の公開QA40問を使い、最終バイナリで131試行を記録した。計数だけの呼び出しは送信トークンに含めない。旧版ではモデルが拒否した生成の入力値が欠測になる。[問題と予算](panel.json)・[追加8問](holdout.json)・[比較条件](protocol.md)

## 回答例と限界

* **会場変更。** 元資料が8,180トークンある235文の記録で、旧版は旧会場と新会場が別区間にあり回答を控えた。`--compact` は各文の出現順を保持し、最終決定の「朝凪公会堂」を元のバイト位置付きで返した。回答と再確認の入力は8,708→768トークンだった。
* **時刻の訂正。** 異なる記録からなる9,903トークンの資料で、旧版はモデル側の拒否で終了した。`--compact=evidence` は230文を2区間で読み、前後の文を含む7文を照合して「9時45分」を返した。この処理は4回の生成に合計12,049入力トークンを使った。
* **撤回と完全一致。** ロッカーの利用コードを撤回した英語の例では、根拠選択後にも旧コードを確定情報として返した。別の日本語の例は曜日を正しく選んだが、助詞を含む「木曜日に」を返し、指定の「木曜日」との完全一致を落とした。引用元を特定できても、その情報が今も有効か、抽出範囲が適切かには誤りが残る。

`--compact` は入力全文を復元できる辞書表現が予算に収まる場合に使用する。収まらない場合は旧版と同じ範囲を順に読む。`--compact=evidence` は、その場合に各区間の根拠を原文の文番号で選ぶ。前後の文を加え、連続した範囲を元の順序で回答と再確認に使う。抜粋に含まれない事実を見落とす場合がある。どちらも対象は `answer` の入力資料で、会話履歴を使うときは発言者と発言順を含めて渡す。

## 改善の経緯

初回104試行では、モデルに「全区間を保持」という真偽値と文番号を同時に返させた。個別の番号を選びながら全体の保持も要求する出力があり、異なる記録の5問すべてが通常読みに戻った。次の131試行では、必要な文番号、根拠無しの空配列、全区間を表す単独の0を区別した。追加の6問で根拠選択が5問に正解した。一方、辞書にできない場合でも再試行用に区間を短くした設定は正解を3問から1問に減らした。最終版では辞書方式で元資料を読む区切りを旧版とそろえ、6問の合否がすべて旧版と一致した。追加問題はこの最後の互換性修正時には既出である。[初回の結果](pilot.jsonl)・[中間版の結果](second-pass.jsonl)・[最終版の実装](https://github.com/ultimate-1113/AFMCLI/commit/2633f7f5cc58fc83996b7a886e5daf6054ea4034)

## 再実行

実機はMac mini M6、メモリ32 GB、モデルの配置先は内蔵SSD 256 GB、macOS 27.2.1（26B131）。実機のモデル表示はAFM 3 Core Advancedで、経路は `system`。各回のタイムアウトは45秒、生成はgreedy、同時実行は1件。標準予算6,200トークンの長文2問のほかに、小さい入力予算を設定した例を含む。最終版の実測バイナリのSHA-256は `c2f2a58ea850c61d3f80422e4510ece3d22e929ac534b80560f43ce9e11cc7a6`。

合成資料を1件試すにはリポジトリのルートで次を実行する。

```sh
cargo build --release --locked
python3 -B eval/context/bench.py show --case repeat-venue | target/release/afmcli --compact run
python3 -B eval/context/bench.py show --case unique-reschedule | target/release/afmcli --compact=evidence run
```

保存した結果の再採点と再計測には次を使う。`--baseline` にはv0.2.0の実行ファイルを指定する。公開QAは配布元の固定ハッシュの入力を読み込み、公開記録には問題ID・得点・測定値を保存した。[公開データの出典と条件](../../NOTICES.md)

```sh
python3 -B eval/context/bench.py verify
python3 -B eval/external.py eval/work/data
python3 -B eval/context/bench.py run --baseline ./afmcli-v0.2.0 \
  --binary target/release/afmcli --data eval/work/data --results eval/work/context-replay.jsonl
```
