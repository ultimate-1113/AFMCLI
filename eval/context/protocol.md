# 文脈圧縮の比較条件

同一のMacで公開版v0.2.0の標準QAと新版の `--compact answer` を、同じ入力・同じ予算で比較する。モデルはオンデバイスのAFM 3 Core Advanced。各条件はgreedyで1回、同時実行1件、裏付けの再確認あり、各fmプロセスの待ち時間は最大45秒とする。各問題内の実行順は問題IDと方式名のハッシュで決める。

合成12問のうち5問は同文を繰り返す通知や会話、5問は異なる記録が続く会話・業務資料、2問は短い対照である。元の決定と後の撤回、再決定、対象の違い、異なる発言者、未解決の矛盾、該当情報の欠落を含む。問題と正解はpanel.json、入力を復元する処理はbench.pyに保存した。新規の10問は長文のための設計例で、独立した第三者の資料に対する一般化を測るものではない。

長文のうち2問は標準入力予算6,200トークン、残りは1,050〜1,300トークンとする。小さい予算は途中で資料を分割した場合を調べるために設定した。短い文章の回帰は従来の日本語・英語の資料QA40問でも測定する。公開データの原文とモデルの回答は配布元から再現できる。

回答の採点には正答文字列と元のUTF-8バイト位置を使う。原文に確定した答えがない設問は、明示的な棄権で正解とする。保留・拒否・時間切れ・実行エラーを正解に含めない。短文の公開QAには従来と同じ採点器を使う。記録する処理量は、検証と再試行を含む全生成への推定入力トークンの合計、1回の最大値、生成回数、CLI起動から応答完了までの時間。トークン計数だけの呼び出しは合計に含めない。圧縮ありは処理経路、保持した文の数、選択を終えた区間数も記録する。
