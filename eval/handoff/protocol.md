# 段階間で渡す文脈の小規模試験

目的は、段階ごとの新規セッションに何を引き継ぐと、入力上限・事実の保持・原文の裏付けがどう変わるかを測ること。AFM 3 Core Advanced、system、greedy、1要求6,200入力トークン、公式fmを用い、要求は直列とする。

独立に作成する日本語の新規8件を、短長それぞれ4件、確定と未確定それぞれ2件とする。1件を時間順の3段階で読む。既にコンテキスト超過を確認した旧試験の補足後1問は、原文を6分割した既知例として別に評価する。

すべての方式で目的・残りの作業・今回初めて読む資料を渡す。途中の出力は短い状態メモ160文字と最大3件の原文ID。次の3方式を同じ入力と出力スキーマで比較する。

- 全履歴では、過去の全資料と過去の各段階の状態メモを毎回渡す。
- 直前出力では、直前の状態メモとその原文IDだけを引き継ぐ。原文IDは最終回答にも使える。
- 原文再読では、直前出力に加えて、その出力が選んだIDの原文を以前の資料から最大3行・合計1,200 UTF-8バイトまで読み戻す。未知のIDを使わず、採点用の根拠から検索しない。

各段階を別のfm呼び出しで処理する。中間のメモ生成を含めて入力・時間・生成数を合算する。上限で送信を見送った場合は別に記録し、採点時は未完了とする。到着順に処理し、途中の失敗を後続段階に正しい答えとして引き継がない。ケースごとに方式の実行順を交替する。

主指標は最終値または正しい未確定判断と、その正式な根拠IDの両方が合う件数。値だけの正答、完了数、未確定への非空回答、送信総量、送信ピーク、待ち時間も示す。短文・長文、既知の失敗例を分け、全方式が完了した同一ケースでも比較する。入力・採点・実行ロジックを初回生成前に固定し、通常CLIへの採否はこの探索的パイロットで決めない。
