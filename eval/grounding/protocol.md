# 撤回・変更の適用先を問う資料QAの比較条件

開発には既出の長文26問を使う。追加評価には15組30問を用意した。各組は質問・冒頭・中段・周囲の点検記録を共有し、末尾近くの告知だけが異なる。15問は原文に確定値があり、15問は確定値が書かれていない。英語8組、日本語7組。展開時は先頭から4行目、中点、末尾から4行目に各通知を入れ、残る行には既存の生成器 `eval/context/bench.py` の `filler` を使う。質問や正解を検索や区間選択に渡す際、正解欄・組名・正解位置は入力に含めない。

追加評価を開く前に実装と実行ファイルを固定する。オンデバイスのAFM 3 Core Advancedをgreedy・同時実行1件で呼び出す。v0.3.1と改善版には同じ入力・指定予算・`--compact=evidence` を使う。また同じ全文をハーネスの `--direct` に渡し、標準の入力予算6,200で1回回答させる。入力超過・モデル側の拒否はそれぞれ別に記録する。各問の条件の測定順はIDと条件名のハッシュで決める。

正解は、事前に指定した値と完全に一致して引用位置も原文と一致する回答、または確定値がない問への明示的な棄権。直接回答には引用位置の出力がないため、値と空回答を採点する。誤った値を返した件数、回答できる問に対する棄権、両方正解した組数、呼び出し回数、入力量、完了時間も示す。改善の採否は既知の事例と追加評価の双方で判定する。標準の確認処理を置き換える条件は、開発・追加評価でともに正解が増え、追加評価で誤った値を返す数が増えないこと。条件を満たさない方法は別条件として実測を残す。
