# 行の取り違えと古い依頼の再適用を測る

3種類の合成表に同じ12シナリオを適用する。各表は、同じ数量の異なる行、利用者が操作を依頼した時点のID・行の版・旧数量、プレビュー時点の表を持つ。古い行番号は全件で1。対象行を並べ替えたり、その前に別の行を挿入したりしても、対象が同一で版が一致すれば完了を求める。数量が一度変わって元に戻った場合、同じIDが2件ある場合、要求済みの変更が再送された場合は保留を求める。版はストアから得た値とし、同じ行の変更ごとに進む。

直接回答には、安定IDと版を含めた依頼と現在の表を渡す。以下の3方式ではRustのローカル処理を使う。

- **行番号と旧値**は元の行番号の値が一致したら変更する。変更時はその位置の現在版を1進める。
- **行番号とID・版**は同じ位置のIDと観測時の版も照合する。値が変われば版を1進める。
- **IDを検索して版を照合**する方式は、指定した配列でそのIDが一つだけかを確認し、その行の版・旧値を照合する。全操作が成立した場合だけプレビューを返す。

入力・正解・実装・採点器を初回のパネル実行前に固定する。全体の最終文書を比較し、正当な変更・確定した無操作・保留を区別する。誤った状態を書いたプレビュー、変更すべきなのに保留した件数を個別に集計する。直接回答は適用前の提案であり、形式不正、無変更の提案、明示的な保留を別々に記録する。この試験は永続ストアの並行書き込みを行わない。
