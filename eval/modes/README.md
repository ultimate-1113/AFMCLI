# 用途ごとの採否と通常版の回帰試験

Mac mini M6、メモリ32 GB、内蔵SSD 256 GB、macOS 27.2.1（26B131）で、通常ビルドからオンデバイスのAFM 3 Core Advancedを呼び出した。QAと翻訳の採用には、すでに公開した合成問題を使った。ここで報告する製品版の数値は、同じ入力をもう一度処理した回帰試験の成績である。[長文と電卓の先行試験](../combinations/README.md)・[翻訳の先行試験](../moe/README.md)

## 資料QA

| 目的 | 採用した方式 | 許容した不利益と採用の条件 |
|---|---|---|
| 原文を開く前に候補を得る `preview` | 最大14区間、合計5,600バイトまでの原文を1回読む。短い原文は全体を渡す | 確定12問中8問以上で正しい値と正式な出典を示し、24問の送信量が旧索引の半分以下、中央値が30%以上短いこと。根拠があっても現時点で有効とは限らないため、返す値はすべて `review`。全文の未確定判定には使わない |
| 既知の決定を拾う `lookup` | 旧索引を採用。必要に応じて再検索・全文走査へ進む | 確定値と正式な出典を4分の3以上の問で得ることを優先。先行48問では確定21/24件、未確定に値を返したのは12/24件。未確定が多い業務では `cautious` を選べる |
| 未確定を断定しない `cautious` | 最初の答えを伏せて同じ根拠を独立再読 | 同じ問題で `lookup` が未確定に値を返した件数の半分以下、確定値の正答は3分の1以上。先行48問では誤答が12→3件、確定値の正答が21→12件。待ち時間の増加と追加の保留を受け入れる用途に採用 |

製品版の `preview` はRust実装で、先行試験のPythonの `packet` と抜粋の選び方や出力契約が異なる。24問の全送信入力は13,451トークン、完了中央値は0.727秒、生成は各1回だった。同じ24問で以前に測った旧索引は168,399トークン、2.643秒だった。確定12問で正しい値と出典を示せたのは8件。未確定12問で候補が出たのは10件だった。候補は実際に提示した抜粋の逐語引用と元のUTF-8バイト位置で検査する。[製品版の全記録](qa.jsonl)・[旧索引の全記録](../combinations/results/qa.jsonl)

長さ（約8K・16Kトークン）と言語（日英）の各組合せから、事前に文書ペアのIDのハッシュで1組を選び、同じ8問を通常版の `lookup` と `cautious` にも渡した。以下の分母は各モードにつき確定4問・未確定4問である。

| 方式 | 確定値と出典が正解 | 未確定を正しく棄権 | 未確定に値を返した | 入力トークンの合計 | 完了中央値 |
|---|---:|---:|---:|---:|---:|
| `lookup` | 3/4 | 1/4 | 3/4 | 70,224 | 2.699秒 |
| `cautious` | 2/4 | 3/4 | 1/4 | 126,709 | 22.328秒 |

採点では保留・エラーも分母に含めた。`preview` で提示した候補を採点するときだけ、その値と引用を既存の確定値用スコアラーで検査した。未確定問への非空候補は誤りに数えた。通常の `answer` は従来の方法を使い、JSONには利用者が指定したQAモードを `metrics.answer_mode` に記録する。[QA集計](qa-summary.json)・[元の採点規則](../index_status/fixtures.py)

## 日英翻訳

`draft` は1回で全文を返し、人が読み直せる用途を対象とする。採用条件は30問中24問以上に下訳が出ること。`checked` は重大な誤りを `draft` の半分以下に抑え、30問中10問以上で全文を返すことを目安にした。原文と訳文の文対応、数値と単位の組、名前、指定訳語を検査し、修正した文を戻して全文を再検査する。意味の向きや行為の時期は独立した採点項目で、公開前の文字列検査を通った訳にも誤りが残りうる。[採点規則と公開入力](../moe/domains/README.md)

| 製品モード | 訳文を返した | 全条件に正答 | 重大な誤りを含む訳文 | 保留 | 拒否 | 完了中央値 |
|---|---:|---:|---:|---:|---:|---:|
| `draft` | 29/30 | 5/30 | 21/30 | 0 | 1 | 0.546秒 |
| `checked` | 10/30 | 9/30 | 0/30 | 19 | 1 | 0.597秒 |

同じ30問を各モード1回ずつ、問題ごとに先に実行する方式を交替して測った。表の「重大な誤り」は、採点規則が検出した数値・単位・名前・意味の反転の件数を、1問1件として数えたもの。保留・拒否も分母に含めている。実行時に指定した名前や用語には日本語も使える。追加の単体テストでは、英訳に残すべき日本語名、数値と単位の入れ替え、原文の丸写しも検査した。[翻訳の全記録](translation.jsonl)・[翻訳集計](translation-summary.json)

## 補助検索と採用を見送った方法

索引を保持する `search serve` では、呼び出し側がAFMの応答も待つときは `interactive`、多数の検索結果を先に使うときは `throughput` を選べる。元の480バッチの比較では、Metalに全件を送ったときのAFMと検索の完了が2.523秒、Core MLと分担したときは2.573秒だった。検索単独では逆に1.237秒と0.842秒だった。製品版は利用者の索引とクエリで速度と整数スコアを照合してから演算先を選ぶ。[AFMと重ねた固定仕事量の試験](../combinations/hardware/batched/README.md)・[製品版の校正条件と実測](../../tools/search/README.md)

製品版で公開ソースの4,096行から索引を作り、新しい2,049問を同順で検索した。索引を保持した状態の6巡で、1要求の往復中央値はCPU限定82.552 ms、対話向け62.624 ms、大量処理向け52.895 msだった。全8,392,704スコアと返却順位が一致した。この試験は検索だけを実行した。Core ML側で確認したのは畳み込みの優先先で、AFM内部の演算先はシステムが選ぶ。[検索の全6巡と実際の演算先](../../tools/search/verification-final.json)

単発の2,049問でプロセス起動のたびに校正すると、対話向けは219.352 ms、大量処理向けは257.951 msかかった。そこで単発の `search query` はCPUで実行する。最終版の新規プロセス3巡では全モードで約95 msだった。[校正を含めた単発の試作](../../tools/search/cold-before.json)・[最終版の単発計測](../../tools/search/cold.json)

- **長文の第3セッション。** 自然に発動した1件で、保留していた撤回済みの値を再び返した。未確定を避ける目的では独立再読を採用した。[変更された判定](../combinations/README.md)
- **文章題の最後の電卓コールバック。** 正解0/16件で、値の決まらない8件すべてに数値を返した。厳しい根拠照合では16件すべてが保留になった。どちらも製品モードへの採用を見送った。式が確定している入力にはRustの `calc`、文章からの提案式には `calc --from-text` の `review` が使える。[文章題の実測](../combinations/README.md)

## 再現

保存済みのモード、元入力のSHA-256、呼び出し回数、全回答・引用を、元の問題と採点コードから再検査できる。

```sh
python3 -B eval/modes/check.py replay --track qa
python3 -B eval/modes/check.py replay --track translation
python3 -B eval/modes/check.py decide --track qa
python3 -B eval/modes/check.py decide --track translation
```

`decide` は各基準の真偽を個別に出力する。速度の参照値は同じ24問で保存された旧索引の値である。ここでの許容幅は今回の用途ごとの運用判断で、先行研究が初見試験前に固定した共通採用条件とは別に定めた。

対応するMacで再測定するときは、モデルのバリアントを確認したうえで、1回につき1要求を順番に送る。各記録に実行ファイルのSHA-256を残す。同じ出力先・同じビルドなら中断したケースの次から再開できる。

```sh
cargo build --release --locked
work=$(mktemp -d)
python3 -B eval/modes/check.py run --track qa --binary target/release/afmcli --out "$work"
python3 -B eval/modes/check.py run --track translation --binary target/release/afmcli --out "$work"
```
