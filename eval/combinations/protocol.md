# 追加の組み合わせ試験の事前条件

基点はAFMCLIの `2683791`。Mac mini M6、32 GB、内蔵SSD 256 GB、macOS 27.2.1（26B131）のオンデバイスAFM 3 Core Advancedを使用する。推論は一度に1件。生成はgreedy、各試行でセッションを新しく作る。安定版v0.4.0の既定値への変更はこの探索の対象外とする。

## 長文

新作24問は8K・16K各6組で、それぞれの組は確定と未確定の2文書からなる。日本語と英語を同数とし、文書はAppleのカウンターで目標の±3%に校正する。原文の値に加えて、それを確定したUTF-8バイト位置を採点する。未確定の正答は明示的な `null` のみ。生成・確認失敗や処理保留は別集計にする。次の7条件を同じ問いで測る。

| 方式 | 比較する処理 |
|---|---|
| indexed | 前回の旧索引を新作で再実行する |
| checked | 前回の独立した再読を新作で再実行する |
| packet | 質問から原文の短い抜粋を選び、1回の読解で出典付きの回答を作る |
| anchored | 索引の回答で引用された位置を抜粋の選択に使い、次の読解で原文から回答を作る |
| selective | 索引が非空値を返し、原文の取消・変更などで誤適用が疑われるときに限り追加確認を試す |
| independent | 索引と、初回判断を参照しない抜粋読解を独立に実行し、結果を合わせる |
| arbitrate | 独立2方式の判断が実質的に対立したときにだけ、短い原文で第3セッションを呼べるようにする |

追加確認1回の入力上限は6,200トークン、第3セッションは指示・スキーマを含む見積もりで850トークン。モデルに送るのは質問と原文から得た情報で、採点用の属性・正答・根拠位置は渡さない。各条件を実機で別々に最初から実行し、計測量を他条件と共有しない。「独立」は判断間の情報の流れを指す。並列化による待ち時間短縮は測定しない。

探索上の成功条件は、旧索引より未確定での非空値が減り、確定問および全体の正答が維持され、総送信入力が旧索引の1.05倍以下、完了中央値が1.10倍以下となること。個々の条件を満たしたかも報告する。経路・稼働した追加確認回数・誤答に変化した問も記録する。

## 関数電卓

新作16問は日英各4組。各組に数値が決まる問と、必要な量や関係が欠けた問を1つずつ含む。正解を数値または明示的な「不明」で採点し、処理保留は失点とする。比較は以下の7方式。

- Swiftの電卓未登録の回答、登録後の最終回答、実際の成功コールバックの最後の値を優先する回答。
- AFMが式を提案しRust電卓で計算する方式と、先に数量・関係・根拠を抽出する段階を挟む方式。
- 電卓の戻り値を使う方式と根拠を抽出する方式を独立に実行し照合する方式と、必要なときだけ照合する方式。

各経路のモデル応答、実際のToolコールバック、ホストから電卓に渡す式、最終回答を個別に保存する。登録後の最終回答と比べ、確定問の正答を維持し、情報不足への数値回答を減らし、合計正答を増やすことを改善条件とする。通常の文字入力の見積もりと、Swiftフレームワーク内部の取得できない入力は区別する。

## 実行・採点

処理の実装と問題の執筆は別の担当が行う。全方式・データ・採点を計測前にハッシュで固定する。各文書内で方式の順を交替させ、各条件を1回実行する。経過時間はホストでの処理からモデルの応答・最終出力の確定までとし、機材確認と試験結果の採点を除く。個々の要求の生出力を保存し、モデルなしで分岐・最終値・採点を再現できるようにする。問ごとに結果を保存し、未完了の比較は同じ指紋で再開する。標本は小さく、同じ組の2問は独立した観測とは扱わない。

## ハードウェア

AFMの実行先指定の有無をこのOSの公開API・CLIで調べる。別の言語モデルを使わず、ハーネスが行う原文の検索得点計算を同じ数値入力でCPU許可・CPUとANE許可の両方で試す。Appleの公開Core MLテンソルAPIで数値結果を回収し、整数での参照計算と照合する。処理先を許可したこと、実行デバイスを観測したこと、AFMの本体が高速化したことはそれぞれ独立に判定する。
