# AFMCLI 0.1.0 実機評価

独立した2組の評価で、Core Advancedへの直接依頼と、同じタスクをAFMCLIに渡した結果を比較した。合成54件では **28件から43件**、既存の公開データ47件では **10件から19件** に増えた。外部データでは12件が正答に変わり、3件が誤答に変わった。直接依頼も、必要な出力項目と形式を指示している。以下の件数は、あらかじめ定めた問題別の条件をすべて満たした数を表す。[事前の条件](protocol.md)・[採点と速度の全数値](results/summary.json)

## 初見の合成54件

各タスク6件を用意した。調整用の文書との重複を避け、日本語と英語、項目の順序変更、撤回、欠落、同じ数値の反復、対象外ラベル、不等号の境界を含めた。

| タスク | 直接 | AFMCLI | AFMCLIで確かめたこと |
|---|---:|---:|---|
| 自由回答 | 5/6 | 5/6 | 指定語・個数・長さなど、各問で定義した条件 |
| 書き換え | 5/6 | 5/6 | 指定した数値や意味を表す語、長さの維持。文体の主観評価は別途必要 |
| 資料に基づくQA | 1/6 | 2/6 | 正答の短い文字列と原文の位置 |
| 項目抽出 | 3/6 | 5/6 | 複数値・欠落を含む全項目と引用位置 |
| 分類 | 3/6 | 5/6 | 任意のラベル・定義を渡し、該当なしを含めて判定 |
| 抽出型要約 | 5/6 | 5/6 | 指定の焦点に合った原文の文集合 |
| 任意スキーマ | 6/6 | 6/6 | 型・全フィールド・値。JSONの整数と真偽値も区別 |
| 条件付き編集 | 0/6 | 6/6 | 文書全体、変更の有無、旧値不一致時の保留 |
| 有界整数最適化 | 0/6 | 4/6 | 実行可能性、解、目的値の列、同率数 |

合成54件で新たに15件が通り、直接依頼の正解から落ちたものは0件。AFMCLIが使ったモデル生成は計52回、直接依頼は54回だった。定型編集と構造化済みの数理問題は通常コードだけで完了する。CLI起動を含む中央値は直接0.331秒、AFMCLI 0.328秒。複数方式が混在するため、個別用途の速度はタスク別の記録を見る。[全54件の正解・原文](heldout.jsonl)・[全試行の回答と処理時間](results/heldout.jsonl)

6組の行動テストでは、同じ意味の言い換えと、意味が変わる変更を元問題と同じ組にした。3問すべてを通したのは直接2組、AFMCLI 3組。たとえば照明の不具合の話から「交換部品をいつ発送するか」へ依頼を変えた例では、AFMCLIは物流を選べず棄権した。モデルの応答を1回調整しても、未知の表現すべてに一般化するわけではない。[組別の成績](results/summary.json)・[行動テストの原典](https://aclanthology.org/2020.acl-main.442/)

数理最適化のうち、利用者が式を渡した3問は3/3。自然言語3問ではモデルが作った式の完全一致は0/3で、最終解は1/3だった。うち1問は「F < 3」を「F ≤ 3」と解釈し、2を選ぶべきところで3になった。別の1問は制約を余分に足しても結論が「実行不能」で一致した。自然言語モードはこれらの式を `review` 付きで返す。[解釈した式と最終状態](results/heldout.jsonl)

## 異なる著者の公開データ47件

公開元の検証用データから固定のハッシュ順で選んだ。同じ記事・画像グループは同一データセット内で1回まで。JSQuADは回答がある16問、SQuAD 2.0は回答あり8問・なし8問。JNLIは3ラベル各5問。全件を分母に含めた。QAの主指標は正規化した文字列の完全一致で、公式ランキングへの提出値とは採点範囲が異なる。[データ選定コードと固定ハッシュ](external.py)・[JGLUE](https://github.com/yahoojapan/JGLUE)・[SQuAD](https://rajpurkar.github.io/SQuAD-explorer/)

| データ | 直接 | AFMCLI標準 | AFMCLI標準の中央値 | 追加確認を省いたQA |
|---|---:|---:|---:|---:|
| JSQuAD 日本語QA | 2/16 | 9/16 | 0.680秒 | 9/16、0.394秒 |
| SQuAD 2.0 英語QA | 3/16 | 3/16 | 0.608秒 | 3/16、0.391秒 |
| JNLI 日本語推論分類 | 5/15 | 7/15 | 0.384秒 | 対象外 |

英語QAで完全一致が増えなかった要因の一つは応答の拒否で、標準方式では16問中9問で発生した。外部47件全体では直接1件、標準11件が拒否だった。拒否を受けた時点でその試行を終了した。公開する外部記録は問題ID・測定値・採点結果に絞った。再実行時は著者の配布データをローカルで使用する。[全件の成績とステータス](results/external.jsonl)

根拠位置が付いた標準方式の外部16回答では、実在するUTF-8区間との照合は全件通過した。引用の実在だけでは、選んだ語句の意味や範囲の正しさは判定できない。合成QAでも「十八時」を求めたのに「十八時に開始」まで返した。SQuADの回答なし8問で回答を出したのは、追加確認を省くと4問、標準で2問だった。速度を重視する用途には `--fast-answer`、答えを出す根拠をもう一度吟味したい用途には標準設定という選択ができる。[ケース別の採点](results/external.jsonl)・[引用の適切さを評価したALCE](https://aclanthology.org/2023.emnlp-main.398/)

## 長文・画像・自動選択

21,249文字の合成資料の末尾に識別子を置いた。直接入力は指示込み13,393トークンで予算を超え、生成前に保留した。AFMCLIは資料を分割して4回生成し、9.30秒で末尾の `QMX-4921` と元の位置を返した。生成上限を1回にすると処理途中で保留となり、部分回答を完了扱いにしなかった。これは1つの長文例である。

画像と標識文字列を一緒に渡す試験では、赤一色の画像から `red`、本文から `QL-639` を取得できた。`auto` が指示から選んだ処理は8件すべてで想定した経路と一致した。この8件は経路選択だけの採点で、各回答の内容の正しさは上のタスク別評価で扱っている。[統合試験の実装](probes.py)・[実機の応答](results/probes.json)

## 調整、固定、再現

最初の8タスク17件では標準候補が13/17、抽出QAの回答可否と分類の該当なしを明示した候補が14/17。整数ソルバーの3件を加えた候補が16/20だった。最後に分類をラベルごとの真偽判定にし、QA候補の意味を別の呼び出しで確認し、書き換え指示の渡し方と数式の表現を調整した構成が20/20だった。ここで方式選択を止め、初見・外部データの生成前にRust実装、問題、採点器と依存のハッシュを固定した。この20件は調整に使ったため、初見の精度とは別に示している。[調整時の全応答](results/development.jsonl)・[固定したファイル](lock.json)・[評価開始前のコミット](https://github.com/ultimate-1113/AFMCLI/commit/52b10f6833690ed6dd40d55757a57519abe65d42)

Mac mini M6、32 GB、内蔵SSD 256 GBにOS管理のモデル、macOS 27.2.1（26B131）、計測用バイナリはApple Silicon向けRust 1.99.1。生成はOS付属のfm、system、greedy、新規セッション、同時1件。バイナリのSHA-256は `7f68677f38640ad1ac9c5bca6c50d3e93be3b867b70961553587fb07855835b2`。標準と比較用は同じ実行ファイルで、各ケースの実行順は固定ハッシュから決めた。小規模な合成試験と公開開発データから、あらゆるタスクでの最適性やモデルの事前学習との非重複は判断できない。

完全なGitクローンでは、初版の実装ハッシュを評価開始時のコミットと照合できる。リポジトリのルートから公開記録を再採点する。外部データの公開記録については件数・項目・集計を照合する。外部QAの本文に照らした再採点には実機の再実行で得られるローカルの生応答を使う。

```sh
python3 -B tools/verify_results.py
```

対応するMacで初版の全件を生成し直す場合は、v0.1.0を別の作業ディレクトリに展開してから以下を実行する（例として `git worktree add --detach ../AFMCLI-v0.1.0 v0.1.0`）。出力ファイルごとに完了したIDと方式を保存する。同じ実行ファイル・条件で再開すると残りのケースを処理する。

```sh
cargo build --release --locked
python3 -B eval/bench.py run --split heldout --modes all --output eval/work/heldout.jsonl
python3 -B eval/external.py eval/work/data
python3 -B eval/bench.py run --split external --modes all --output eval/work/external.jsonl
python3 -B eval/bench.py verify --split external --output eval/work/external.jsonl
python3 -B eval/probes.py target/release/afmcli eval/work/probes
```
