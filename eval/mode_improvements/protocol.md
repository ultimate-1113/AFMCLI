# 用途別モード改善の事前条件

基準はコミット `beeb6944946471e12c5de43834f87a84c32ca9f4`。Mac mini M6、32 GB、内蔵SSD 256 GB、macOS 27.2.1（26B131）、オンデバイスのAFM 3 Core Advancedを使う。実行開始時にモデル名を確認する。実行ファイルと結果は外部SSDの独立したフォルダに置く。1生成あたり入力予算6,200トークン、モデル側の公称コンテキストはこの端末で8,192トークン。通常CLIのgreedy設定を使う。

## 入力と順序

開発用はQA12問、翻訳12件、文章題8問。初見試験はQA48問、翻訳40件、文章題24問。問題、正式な根拠のバイト位置、補足回答、採点器、採用基準を実装前にハッシュで固定する。開発用と初見用の題材を分ける。採点器・正解・ケースIDをモデルに渡さない。基準と候補は同じ入力で測定し、ケース・モードにより実行順を交替する。確認質問への再回答は初回と別に集計する。失敗の後も記録を残し、全件を分母に含める。

QAの初見は日英の4K・8K・16K各群に4組ずつの確定・未確定ペア。未確定24問の半数は利用者の補足で解決でき、残る半数は資料で確定していない。確定では答えと正式な根拠のUTF-8位置、未確定では返した値の有無を採点する。根拠を読み込めたかは、記録された送信範囲で確認できた場合だけ判定する。確認は基準日・対象・条件のうち利用者が解消できる不足を具体的に1点尋ねる。補足のある状態でも原文の正式な根拠を要求する。バッチは入力待ちにしない。

翻訳の初見は各方向20件。数値と単位の対応、指定表記、名前、文に対応する内容、比較の境界、時期・肯否・動作を独立に採点する。開発用で現行、文IDだけ、数値と単位等の保護だけ、両方を比較する。初見に進めるのは各モード1方式。候補の選択は、まず開発用で各モードの重大誤りと提出件数の条件に近い方式、次に全条件正答、同率なら少ない呼び出し、最後に速い方式を優先し、初見前に選択を記録する。

文章題は日英の確定・不足ペア。合計、差、単価と個数、割合を扱う。数値の決まる問の正答、数値の決まらない問に返した数値、不足している項目への具体的な指摘を別に採点する。一般的な保留やシステムエラーは「不足を特定できた」件数に含めない。

## 採用条件

以下の条件を各モードですべて満たした変更だけを通常版に入れる。割合を比較する場合は丸める前の値で判定する。QA・翻訳の完了時間はCLI起動からJSON出力まで。総入力は全生成を合算する。運用エラーが生じた試行も正答には数えない。

| モード | 初見で満たす条件 |
|---|---|
| preview | 未確定の非空候補が基準の半数以下。確定正答を最大1件までの減少にとどめ、全件1生成以下。総入力が基準の1.05倍以内、完了中央値が1.10倍以内 |
| lookup | 確定正答が基準以上、未確定の非空回答が基準より少なく、完了中央値が1.10倍以内 |
| cautious | 未確定の非空回答は基準以下かつ2件以下。確定正答が2件以上増え、12件中10件以上で正しい確認質問を提示し、ほかの36件への不要な質問は1件以下。中央値は基準の1.25倍以内 |
| draft | 40件中36件以上で下訳を返し、重大な誤りを含む出力が基準の半数以下。最大1生成 |
| checked | 各方向10件以上、全体で24件以上を返し、返した訳の重大誤り0件、返した訳の全条件正答率90%以上。最初の翻訳と修正を合わせて最大2生成 |
| calc --from-text | 確定の12問中8問以上に正答。不足12問への数値0件、10問以上で具体的な不足を特定 |

単発と常駐の補助検索は、前回と同じ公開ソース・2,049件のクエリで全スコア・順位の一致と待ち時間を再確認する。検索デバイスの計測はテキスト生成と別に行う。通常版に採用されなかった候補も、生の判定・差分・再現方法を記録する。公開物は既存のローカルパス、個人識別子、PNGメタデータ検査を通す。
