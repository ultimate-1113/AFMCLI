# 撤回と再確定を扱う索引検索の事前条件

基点は AFMCLI `2f1778cd0d415ad11f2baefab2d8be3f6cfac821`。Apple M6、32 GB、内蔵SSD 256 GBのMacで、`fm respond --model system --greedy` を使用する。実行時にCore Advancedの利用可能表示を確認する。モデルへの入力上限は6,200トークン、実行は直列。比較するのは同じ1モデルに渡す処理手順である。

| 方式 | 操作 |
|---|---|
| records | v0.3.2の通常版。従来の可逆な圧縮と全文の窓分け |
| indexed | 前回凍結した索引。原文を最大2回検索して必要時に全文走査 |
| checked | 索引で求めた原文から決定状態・値・決定を示す文を取り出す。次の呼び出しで質問と原文を独立に読む |
| handoff | checkedと同じ2回目の読解に、1回目の実際の出力を圧縮した状態と根拠を参考情報として加える |
| review | handoffと同じ読解が状態または値で食い違ったときだけ、短い原文から第3の独立確認を最大1回行う |

2回目には質問と原資料を渡す。1要求に収まる資料は全文、収まらない長文は元ファイルの引用範囲を使う。引き継ぎは正解ラベルを参照しない。原文に対応した値とバイト位置を採点する。既存の確認呼び出しも別セッションのため、独立読解と引き継ぎ付きを同じ入力で比べる。候補が一致する問で第3確認の呼び出しが増えていないかも確認する。

## 新しい評価問題

日本語と英語の合成文書を使い、質問と周辺の文章を共有する2件を1組とする。一方には確定した値があり、他方では値が未確定となる。別の対象だけの訂正や再確定を含める。開発は4K・8K・16K各2組の12件、初見は各8組の48件。基準は1K = 1,024トークン。Appleのカウンターで各文書を目標の±3%に校正する。同じ組の2文書には同じ件数の背景記録を挿入する。モデルに渡すフィールドはタスク、質問、資料本文のみ。

初見問題は実装担当と分けて作成し、全問・正解・証拠位置と採点器を固定する。候補の調整は開発セットだけで行う。実装とバイナリを固定して、初見の各問で5条件を実行する。問題IDから固定した順序を使い、各方式が決まった位置に偏るのを避ける。旧30問は既知問題として別集計する。

## 成功の判定

- 未確定24問では、値を設定した回答を誤答とする。正しい棄権は回答値が `null` のときに限る。保留・拒否・実行エラーを成功に含めない。確定24問は原文上の正しい値と正式な根拠位置の両方で判定する。同じ文面の旧値にだけ一致した場合は誤答とする。
- 品質面では、旧indexedより未確定の非空回答が少ないこと、確定値の正答と全体の正答が減らないことを求める。さらに、recordsより未確定の非空回答が増えていないかを検査する。
- 速度・入力面の主対象は8Kと16Kの32問。旧indexedと同じ新問で、合計送信入力は1.05倍以内、完了時間の中央値は1.10倍以内、両指標ともrecordsを下回ることを求める。4Kは全文を読める対照として独立に報告する。元の索引で得た節約幅のうち何割を維持したか、p95・生成回数・最大の入力も示す。
- 採用候補は上の条件をすべて満たした方式から、未確定の非空回答が少ないもの、確定正答が多いもの、長文の合計入力が少ないものの順に選ぶ。同率なら長文の完了中央値を使う。通過方式がなければ、同じ順序で既知30問に照らす研究用の候補を選ぶ。通常版への採用には旧30問でも旧indexedより正答が減らず、未確定回答が増えないことを確認する。
- 手法の組み合わせは同じ問題ごとに比べる。checkedとhandoffの勝ち・負け、最初の値が誤っていて二度目にも引き継がれた件数、引き継ぎで正された件数、第3確認の発動数・結果・費用を記録する。測定時間はCLIプロセス起動前から最終JSONを受け取るまで。総入力には読解、追加確認、再取得とフォールバックを含む。途中で停止した場合は保存済み結果を照合してから再開する。
